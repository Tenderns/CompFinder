## 更换为 DINOv3（2026-10-27）

图片模型由 DINOv2-small（224）换为 DINOv3 ViT-S/16（448），两个模型文件固定 SHA-256。加载时用一张 448×448 空白图检查输出是否为 1 个 CLS、4 个 register 和 28×28 个图块；不符合时引擎报错，不建立索引。向量版本随之变化，旧向量自动失效并重新排队。

新增后端测试 3 项：模型缺文件或校验失败、安装脚本拒绝未校验的来源、特征池化跳过 register token。预处理测试改为 448。这些测试、真实模型加载及检索效果尚未在本环境运行。

## 自动化验收

后端测试使用可预测的独立特征编码器，验证业务与排序契约，不将模拟编码器的结果视为真实模型的准确率。

- 空图库、草稿和可检索状态；展示图永不生成向量。
- 搜索/浏览响应没有识别图信息，识别图不能通过普通图片接口访问。
- 多图平均、每查询图最佳参考、款式去重、重复输入去重、独立框选。
- 查询图片不保存到图库。
- 两套集合内去重，跨集合可分别添加。
- 封面只能属于本款展示集；展示排序有效；删图、删款立即生效。
- 款式信息可为空、可整体替换，空行去除，缺名称或含控制字符时拒绝；普通接口和搜索结果返回款式信息，查找可匹配参数；旧数据库自动补列。
- 导入预览、同名跳过、目录跳转拒绝、损坏图片部分失败和草稿保存；款式信息文件的解析、校验，以及对同名款式的信息替换。
- 重启恢复、向量版本失效、缺少模型、推理失败重试。
- 非图片、动画、尺寸/文件大小/查询数量/框选参数校验。

前端测试覆盖多图提交、自动搜索、删除其中一张保留其余照片、六张上限、预览资源释放、空图库操作状态、从图库带入查询图、款式信息编辑保存及关闭前的未保存提醒。

浏览器检查覆盖桌面和手机宽度，创建款式、分区上传、识别完成、搜索、展示集浏览和删除。测试数据只进入临时数据目录，正式图库保持为空。

## 真实照片评估

准备至少两个目录：图库识别照片和独立拍摄的查询照片。查询照片不可与识别照片相同，也不要仅通过裁剪、缩放同一原图冒充独立照片。

每个查询记录预期款式、前 1 个结果、前 5 个结果及是否命中，分别统计单图和多角度照片的 Top-1 / Top-5 命中率。保持相同模型与图库版本，记录图库款式数、参考图片数、查询数及不同角度覆盖情况。

可使用 `scripts/evaluate.py --manifest <清单.json> --output <报告.json>` 对已建立的图库进行评估。清单格式如下，`images` 相对清单位置解析：

```json
[
  {"name": "查询组1", "expectedStyleId": "图库中的款式ID", "images": ["queries/front.jpg", "queries/side.jpg"]}
]
```

该脚本会输出每个查询的前五结果及汇总，但不会修改图库。数据不足时保留结果，不外推识别准确率。真实评估需在你上传图库并提供独立查询照片后进行；同图回查只能验证技术链路。
