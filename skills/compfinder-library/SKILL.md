# CompFinder 建档

CompFinder 是以图寻物图库。每个款式有：

- **展示图**：给人看的图。用户交给你的那张图放这里。
- **识别图**：以图搜图时比对的参考图。要找同一型号的其他图片，最好是不同角度的实拍。
- **款式信息**：参数、视觉信息、备注。视觉信息必须符合 ytst 轻触开关规范 v1.1。

需要 CompFinder 的 MCP 工具（令牌可能只开放其中一部分）：`search_by_image`、`read_page`、`preview_image`、`visual_taxonomy`、`list_styles`、`get_style`、`create_style`、`add_images`、`update_style_info`、`library_status`。如果没有这些工具，告诉用户先按 CompFinder README 的“AI 建档（MCP）”一节连接，不要假装已建档。如果缺少 `create_style`、`add_images` 等写入工具，说明这个令牌只读：只做查重和识别，并请用户在“AI 接入”页给令牌加上写入权限。

## 图片怎么交给工具

工具只接受三种图片来源：

1. 公网 `http(s)` 图片链接。
2. `data:image/...;base64,...`，只适合很小的图。
3. `upload:<id>`。

用户在对话里贴的图片，你看得到，但拿不到文件本身。处理顺序：

- 用户给了网址：直接用。
- 用户给了本机文件路径，而你能运行命令：先上传，再用返回的 `id`。`COMPFINDER_TOKEN` 是连接 MCP 用的同一个 MCP 令牌。

  ```bash
  curl -s -H "Authorization: Bearer $COMPFINDER_TOKEN" -F "file=@/path/to/photo.jpg" https://<服务地址>/api/uploads
  ```

  ```powershell
  Invoke-RestMethod -Method Post -Uri https://<服务地址>/api/uploads -Headers @{Authorization = "Bearer $env:COMPFINDER_TOKEN"} -Form @{file = Get-Item 'D:\photo.jpg'}
  ```

  `upload:<id>` 只在 1 小时内有效。

- 两者都没有：请用户提供图片的网址或本机路径，并说明原因。

## 流程 A：用户给一张图片

1. **看图、框选。** 用 `preview_image` 看图。如果画面里不止这一个开关，用 `crop` 框住目标，后面的工具都带上同一个 `crop`。
2. **查重。** 用 `search_by_image` 搜这张图，逐一对比前几名的缩略图和款式信息。相似度只用于排序，不是正确概率。
   - 有明显是同一款的：告诉用户是哪个款式，问是往这个款式里补图，还是仍要新建。用户确认前不要新建。
   - 没有：说明“库里可能没有”，继续建档。
3. **识别视觉信息。** 先调用 `visual_taxonomy`，按图片填视觉信息，优先填 8 组关键结构。只写照片里能确认的字段，看不清就省略，不要猜。图上能看清丝印或型号的，记下来备用。
4. **找同款图片作为识别图。**
   - 用你自己的网页搜索功能，按型号、品牌和关键结构搜索，例如“TS-6606 轻触开关 实拍”“6x6 tact switch 4 pin through hole”。
   - 对搜到的商品页调用 `read_page`，拿到候选图片地址。
   - 用 `preview_image` 逐张查看，只保留明显是同一款的图。判断标准见下文“同款判断”。
   - 优先选实拍和不同角度的图：顶面、侧面、底面引脚、焊在板上的。图里混有别的东西就框选。
   - 不要用：同一页面上明显不同的规格、尺寸图纸、只有文字的图、几乎重复的图。
   - 目标 3～8 张。一张都找不到时，告诉用户这个款式会先保存为草稿（缺识别图），并问是否把用户给的图同时作为识别图。这样能先被搜到，但效果较弱。
5. **建档。**
   - 先用 `list_styles` 按型号查一遍是否已有同名款式。
   - 调用 `create_style`：
     - 名称：用型号；不知道型号时，用“类别 + 关键特征”，并告诉用户。
     - `visual`：上一步识别的视觉信息。
     - `params`：只写网页或资料里明确写着的参数，不要推测。
     - `notes`：写明信息和图片来源网址，并注明“AI 建档，待人工复核”。
   - 调用 `add_images`：`role: "display"` 放用户给的图；`role: "recognition"` 放第 4 步选出的图。
6. **复核并汇报。** 用 `get_style` 确认结果，然后按下文“最后给用户的汇报”的格式回复用户。

## 流程 B：用户给一个商品网址

1. **读页面。** 调用 `read_page`。
   - 从标题和正文里提取型号、品牌、尺寸、电气参数等，作为 `params`。
   - 从图片列表里找主图：通常是“页面主图”或第一张商品图。用 `preview_image` 确认后，作为展示图。
   - 页面里同一产品的其他角度图，作为识别图候选。
   - 如果 `read_page` 读不到内容（要登录或完全靠脚本渲染），改用你自己的网页读取工具；还不行就请用户贴出参数或图片网址。
2. **查重。** 用主图调用 `search_by_image`，再用型号调用 `list_styles`。判断方式同流程 A 第 2 步。
3. **识别视觉信息。** 同流程 A 第 3 步。页面文字写明的结构可以采用，比如“贴片”“侧按”“带支架”，但取值必须换成规范中的写法。
4. **补充识别图。** 页面里的图不够或都是渲染图时，按流程 A 第 4 步再搜同款。
5. **建档、复核、汇报。** 同流程 A 第 5、6 步。备注里写上原网址。

## 同款判断

以下各项都一致，才算同一款：

- 本体轮廓和长宽比例
- 本体厚薄
- 脚数、端子样式、端子分布
- 安装方式、按压方向
- 按柄轮廓和颜色
- 有无独立键帽、支架、灯

照片看不出绝对尺寸。6×6 和 12×12、不同高度的同系列产品，要靠页面上的规格区分。规格对不上就不算同款。

拿不准时宁可少放：识别图放错了，会让以后的搜索找错。

## 规则

- 视觉信息不符合规范时，`create_style` 和 `update_style_info` 会报错并列出可选值，按提示改正后重试。
- `update_style_info` 只替换你传入的部分（visual、params、notes 中的一部分），其余保持不变。
- 不能删除款式或图片。发现放错了，告诉用户到网页管理端删除。
- 识别图在后台建立索引，刚加入时 `pendingCount` 大于 0，属于正常现象。
- 用户一次给多个图片或网址时，逐个处理。每个款式建完先简要汇报，全部完成后再汇总。

## 最后给用户的汇报

用这个格式：

```
已建档：<款式名称>（<新建 / 补充到已有款式>）
- 展示图 N 张，识别图 N 张（索引中 N 张）
- 视觉信息：安装方式 插件；按压方向 顶按；……
- 参数：原厂料号 …；额定电压 …（来源：<网址>）
- 存疑：<看不清或没把握的地方，或“无”>
```
